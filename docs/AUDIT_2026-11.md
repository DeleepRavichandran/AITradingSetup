# Independent audit, November 2026 — findings and corrections

Five priorities were raised by an independent audit of branch `claude/practical-maxwell-un2bhi`.
Each was reproduced with a test that failed on the existing code, corrected with the smallest
change that fixes the cause, and re-tested. Tests live in `tests/audit/`.

Live order routing was not touched and remains disabled.

## 1. Sandbox for AI-generated code

**Reproduced.** The same probe script was run under the old and new launchers:

| Probe | Before | After |
|---|---|---|
| read a file elsewhere on the host | readable | denied (does not exist in the sandbox) |
| read the repository's `.env` | readable | denied |
| write to the dataset directory | allowed | denied (read-only) |
| write to `/usr` | allowed | denied |
| uid of the generated code | 0 (root) | 65534, all capabilities dropped, no_new_privs |
| host processes visible | 81 | 3 (own PID namespace) |
| network | blocked *if* `unshare` happened to work | blocked always |
| isolation unavailable | code ran anyway, without network isolation | code is **not run** |

**Root cause.** Isolation was a network namespace only, applied opportunistically; the child
inherited the host filesystem and the launcher's uid. Static validation was the only real barrier.

**Correction** (`services/research/sandbox.py`). Generated code now runs in private mount,
network, PID, IPC and UTS namespaces, in a root that contains only the Python runtime, the
research packages and the dataset (all read-only) and one writable work directory. Privileges
are dropped before the code starts. The execution, API, agent and notifier packages are not
mounted at all. Run artefacts are copied out by the parent. If the namespaces cannot be set up,
`run_jobs` returns an error and executes nothing; there is no override.

Found while verifying in Docker: `pivot_root` is refused inside a container. A fallback (move the
private root over `/`, then `chroot`) is used there; a test confirms the unprivileged child cannot
`chroot` or regain uid 0.

**Remaining limitations.**
- Kernel namespaces are not a hardware boundary. A kernel exploit defeats them; for hostile code
  at scale use gVisor or a microVM.
- No seccomp filter and no cgroup limits (CPU/memory are rlimits only).
- In Docker the API process must run as root with `CAP_SYS_ADMIN` and AppArmor unconfined to build
  the namespaces. That widens what a compromise of the *API process* could do. Without those
  settings the sandbox fails closed and research is unavailable.
- Results returned by the child are trusted as data (metrics could be forged by code that got past
  static validation).
- Windows and macOS hosts cannot run generated code at all.

## 2. Forced liquidations in the backtest engine

**Reproduced** (5 failing tests). A margin call or intraday square-off was filled at the close of
the very bar that triggered it, for the full quantity, ignoring volume; a position with no bar
was "sold" at its last known price.

**Root cause.** `_force_close` bypassed the order queue and the execution simulator.

**Correction** (`services/backtester/engine.py`). A forced exit is now an ordinary market order
flagged `forced`: first tradable on the next bar, needs volume, obeys the participation cap, pays
spread and impact, and stays working until the position is flat. Strategies cannot cancel it or
open new positions in a book that is being liquidated.

| Case | Before | After |
|---|---|---|
| margin breach seen at bar 2 close (17,000), bar 3 opens 16,500 | sold at 17,000 on bar 2 | sold at 16,500 on bar 3 |
| 100 units to liquidate, next bars have volume 0, then 500, then 10,000 (10% cap) | all 100 on the trigger bar | 0, then 50, then 50 |
| square-off at 15:20, 15:21 has no volume | filled at the 15:20 close | filled at the 15:22 open |
| no tradable bar left in the session | filled at a stale price | carried overnight, flagged, exits next open |

Golden regression hashes are unchanged: none of the pinned runs had a forced exit.

**Remaining limitations.** A real broker squares off at its own time and charges a penalty or
auction price for anything left; the carried position is flagged but no penalty is modelled.
Margin is still checked at bar closes only, so an intrabar breach is seen late. A split while a
liquidation order is working cancels and re-issues it.

## 3. Expiry settlement and margin

**Checked against NSE's published settlement rules** and broker worked examples (sources below).
Nine tests; seven passed on the existing code.

| Rule | Engine |
|---|---|
| index futures/options settle at the underlying index's closing price on the last trading day | matched |
| futures final P&L runs from the previous day's settlement price | matched |
| exercise STT 0.125% of intrinsic value: 22,500 call, index 22,600, lot 50 → ₹6.25; intrinsic 200, lot 75 → ₹18.75 | matched |
| 0.15% from 2026-04-01 | matched |
| out-of-the-money and short positions pay none | matched |
| **before 2019-09-01 the tax base was the full settlement value** | **wrong: charged ₹6.25 where ₹1,412.50 was due** → corrected |

**Correction.** The STT schedule gained an effective-dated tax base; the engine passes the
settlement price.

**Margin: not reconciled, and cannot be from here.** The model is flat percentage rates plus
maximum-loss margining for defined-risk option structures. Exchange SPAN figures come from
licensed daily parameter files; none are available, and I did not invent any. What was added is
the tool to measure the gap: `scripts/reconcile_margin.py` takes positions, prices and the margin
your broker or the exchange quoted, and prints the model's deviation. Until someone runs that
with real figures, **treat every margin-dependent result (leverage, margin calls, short-option
capacity) as approximate.**

**Other remaining approximations.** Daily futures settlement uses the bar close rather than the
contract's last-half-hour average (changes the day-to-day timing of cash, not total P&L). Stock
derivatives are cash-settled and flagged, though NSE settles them physically. STT rates before
2023 remain unverified.

Sources: [NSE equity derivatives settlement price](https://nseindia.com/products-services/equity-derivatives-settlement-price) ·
[NSE settlement mechanism](https://nseindia.com/products-services/equity-derivatives-settlement-mechanism) ·
[NSE STT page](https://nseindia.com/products-services/equity-derivatives-securities-transaction-tax) ·
[Zerodha bulletin, exercise STT from September 2019](https://zerodha.com/marketintel/bulletin/230019/no-more-stt-trap-on-exercised-options-from-today) ·
[Upstox, STT worked example](https://help.upstox.com/support/solutions/articles/149318-what-is-stt-securities-transaction-tax-) ·
[Samco, STT rates](https://www.samco.in/help-support/?p=25745).
The NSE pages were found by search and not opened directly from this environment.

## 4. Authentication and authorisation

**Reproduced** (5 failing tests). With no token set, every route — including starting research,
placing paper orders and the kill switch — answered anyone who could reach the port. The
interactive docs and schema were served without authentication even when a token was set.

**Root cause.** Authentication was opt-in.

**Correction** (`services/api/main.py`).

| | Before | After |
|---|---|---|
| start without `NSEQL_API_TOKEN` | starts, fully open | refuses to start |
| token strength | any | at least 24 characters |
| roles | one | operator (all) and optional read-only viewer (`NSEQL_VIEWER_TOKEN`, GET only; refused writes are audited) |
| `/api/docs`, `/api/openapi.json` | open | removed |
| `/api/health` | included version | liveness only |
| unauthenticated use | default | only with `NSEQL_ALLOW_INSECURE_LOCAL=true`, loopback clients only, and not when forwarded from another host |

**Remaining limitations.** Shared static tokens, not user accounts: no per-person identity,
expiry, rotation, rate limiting or lockout. The operator name typed into the kill-switch form is
self-declared. Put the deployment behind a VPN or identity-aware proxy if more than one person
uses it. Insecure-local mode must never sit behind a reverse proxy on the same host.

## 5. Volume reservation, OCO and multi-leg matching

**Reproduced** (5 failing tests, 1 already passing).

**Root cause.** Matching reserved bar volume for every candidate order in a first pass and
decided OCO winners, group completeness and margin afterwards. Orders that were then dropped had
already consumed volume.

| Case | Before | After |
|---|---|---|
| stop and target both reachable, volume covers one | **target filled** (the favourable one) | stop fills (worst case) |
| cancelled OCO sibling | used up volume another order needed | uses none |
| multi-leg group that cannot complete | blocked an unrelated order on one leg's symbol | reserves nothing |
| order rejected for margin at the fill price | kept its volume | releases it |
| two spreads competing for one spread's worth of volume | — | one fills whole, the other does not half-fill |

**Correction.** One pass: reachability, then OCO resolution, then sequential allocation in
submission order where an order takes volume only when it actually fills.

**Remaining limitations.** Priority is submission order, not price-time. Each symbol's volume is
independent. An OCO winner that finds no volume blocks its sibling for that bar (conservative).

Caveats on the Docker results: the build environment reaches the internet only through an
HTTPS-only proxy, so the images were built from a copy of each Dockerfile with two extra lines
that trust the proxy's certificate. The committed Dockerfiles are otherwise identical. An `apt-get`
step that could not work through that proxy turned out to be unnecessary and was removed. The web
container and the full compose stack (including Caddy/TLS) were **not** run.
