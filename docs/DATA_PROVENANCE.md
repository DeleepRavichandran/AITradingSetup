# Data provenance

## What data exists in this project

| Dataset | Real? | Source | Licence | In the repo? |
|---|---|---|---|---|
| `synthetic_v1` | **No — generated** | `nseql.data.fixtures.generate_fixture`, seed 20240101 | none needed | No (regenerated by `nseql fixtures`) |
| `tests/fixtures/*.csv` | **No — made-up values** in the exchange file layout | hand-written | none needed | Yes |

There is **no real market data** in this repository or its test suite. No price, premium, fill or
result presented anywhere came from NSE or a vendor.

### The synthetic fixture

12 equities across sectors (one delisted mid-sample, one listed late), a 1:2 split, nine
dividends, an equal-weighted index, monthly index futures and — from 2022 — monthly option chains
priced with Black-Scholes on a skewed, regime-dependent volatility surface, plus 1-minute bars for
two symbols. Weekdays only; no exchange holidays. Returns come from a three-state volatility
regime model with built-in return persistence in several names.

**Consequence:** trend and breakout rules do well on it *by construction*. A strategy "passing"
on the fixture is evidence that the pipeline runs, not that the idea has merit.

## Bringing in real data

No unauthorised scraping, and no redistribution. Two supported routes:

1. **Files you already hold.** `nseql import-bhavcopy <dataset_id> <files…> --licence "<basis>"`
   reads NSE end-of-day files (legacy CM, legacy F&O with lot sizes supplied, and UDiFF) from
   disk. It never downloads. Each file is copied byte-for-byte to `raw/` with its SHA-256;
   dropped rows and derived series are recorded in the manifest's audit list.
2. **A broker or vendor API you subscribe to.** `KiteHistorical` (unverified) or
   `import_csv` for vendor exports. Credentials come from environment variables only.

After importing: open *Data Quality & Coverage*, resolve errors, then supply corporate actions
(bhavcopies are unadjusted) and a holiday calendar. `nseql corporate-actions <dataset>` lists price
drops that look like unlisted splits or bonuses; confirm each against the exchange's corporate
announcements and attach the real ones with `--file` (a new dataset version; the parent's hash is
recorded). An action is refused when the prices do not drop on its date, which is what already-adjusted
data looks like. `nseql holidays` stores the NSE holiday list with its source and the years it covers. Check your licence before sharing any report
that embeds prices.

### Verifying the Angel One feed (`nseql angel-verify`)

Live 1-minute data is labelled **"Live 1-minute candles (adapter not verified)"** on every page until the
operator runs `nseql angel-verify` with their own `ANGEL_*` credentials during market hours (09:20-15:25
IST) and every check passes: credentials, TOTP login and a 0600 session file, session reuse and recovery
from a corrupted token, the scrip master and watchlist, candle format and bar stamping, the in-progress
minute never passed on (and whether the last bar is revised), paced vs burst rate limits, fast failure on
an unreachable host, stale-symbol detection, and a scan proving the report holds no secret. The report is
written to `experiments/angel_verification.json` (client code masked; a report containing any secret is
not saved). Only `passed: true` changes the label to "verified". **As of 2026-11-21 this has not been run:
no credentials are available in the development environment; the adapter remains mock-tested.**

Derivative symbols are built as `<UNDERLYING><YY><MON><DD>FUT` / `…<STRIKE><CE|PE>`. Index levels
are taken from the `UndrlygPric` column of UDiFF F&O rows as a close-only series (recorded as
derived). Assumption to confirm on your first real file: UDiFF `TtlTradgVol` is in units, not lots.

### `rules/market_structure_in.json` — structural timeline

25 dated events (venue and product launches, settlement-cycle changes, tax changes, margin
framework, expiry rules). **It is a curated reference list, not a history of the Indian market and
not a news archive.** Only the three STT entries from 2023 onward are marked verified; the rest
were written from memory and are flagged `verified: false` in the file and in the dashboard.
Real-data backtests list the structural breaks inside their window as warnings.

### Angel One SmartAPI

`nseql import-angelone` and the live screening feed use Angel One's SmartAPI (free for Angel One clients),
with automatic daily login via TOTP. Credentials are read from `.env` only. Raw responses are kept
byte-for-byte as for every import. Angel One reports no history for expired F&O contracts and current
listings only. Per-request day limits apply (30 days of 1-minute data per request). **Unverified**: tested
against a simulated server only.

### TradingView chart exports

`nseql import-tradingview <dataset> "NSE_RELIANCE, 1D.csv" ... --licence "..."` reads files exported by
hand with TradingView's "Export chart data" (a paid-plan feature as far as we know). TradingView has no
public data API and forbids scraping, so nothing is fetched automatically. Symbol and interval come
from the default file name. The time column may be Unix seconds, milliseconds or ISO text; dates that
cannot be NSE data are refused. Bars are restamped from bar start to bar end. History length depends on
the TradingView plan. Check TradingView's terms before using exported data in other software.

### Market context

`nseql import-context` builds a separate context dataset from Kite (India VIX, NIFTY 50 and 8 sector
indices, USDINR futures, MCX crude and gold; futures use Kite's continuous series). It is never mixed
into a trading dataset. Currency and commodity closes come after the stock market closes, so they are
used from the next trading day. Raw responses are kept byte-for-byte like any other import. Global
markets (S&P 500, US yields) are not included: no licensed source has been chosen.

### Scheduled events

`nseql events` stores results dates, RBI policy, the Union Budget and US Fed decisions from a CSV you
compile from exchange filings and the official calendars. Each needs `known_from` (when it became
public); an event is only used from the trading day after that. Monthly F&O expiry dates are generated
from the exchange rule (switch to Tuesday dated 2025-09-01, unverified). None of this ships with the code.

### News and events

None shipped. `EventStore` is the ingestion and as-of query layer for a feed you license. A
complete, timestamped news history for Indian markets is a commercial data product; it cannot be
reconstructed from a model's memory without inventing it, so it has not been.
